# Demo Dataset

[scenarios.json](scenarios.json) defines deterministic logical inputs for `make demo-seed`. Records are created through the existing REST APIs; UUIDs are generated by the application and saved in `target/local-demo/seed.json`. There are no direct domain SQL inserts and no demo Flyway migration.

| Resource | Final baseline state |
| --- | --- |
| Customers | 5: Alice/Bob/Carol active; Drew inactive after DELETE with an order; Eve inactive via PATCH without orders |
| Products | 8: 7 active; Legacy Item inactive |
| Orders | 4; each contains 2 distinct items |
| Order items | 8 |

| Order | Customer | Items | Subtotal | Discount | Total |
| --- | --- | --- | --- | --- | --- |
| 1 | Alice | Keyboard ×1; Mouse ×2 | EUR 100.00 | EUR 10.00 | EUR 90.00 |
| 2 | Alice | Notebook ×2; Pen ×2 | EUR 35.00 | EUR 0.00 | EUR 35.00 |
| 3 | Bob | Monitor ×1; free Sticker ×1 | EUR 99.99 | EUR 0.00 | EUR 99.99 |
| 4 | Drew | Desk ×1; Mouse ×2 | EUR 150.00 | EUR 15.00 | EUR 135.00 |

After the orders are created, Keyboard is renamed to `Demo Keyboard v2` and repriced from EUR 50.00 to EUR 60.00. Order 1 retains the original name, price and totals. Drew's DELETE deactivates the referenced customer without deleting the order. No later customer or product reactivation is attempted.

The seed checks an empty database before writing and refuses subsequent runs. Partial failure is not automatically retried. Additional manual curl requests change these expected counts. For an explicit disposable restart, see the [local demo guide](../../docs/06-operations/local-demo.md#stop-the-demo).
